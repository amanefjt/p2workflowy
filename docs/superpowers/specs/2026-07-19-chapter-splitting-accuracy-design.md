# 書籍モード 章分割精度の改善（I-22 / I-24 / I-25）

- 日付: 2026-07-19
- 対象: `core/engine/p1_ingest/pdf_splitter.py`
- 関連: `docs/management/troubleshooting_log.md` I-22 / I-24 / I-25
- スコープ外: I-21（VLM スライディング OCR の図版頁重複）— 原因は特定済みだが層が異なるため別スペック

## 1. 背景と問題

Spec B（VLM ルーティング修理）完了により、書籍モードで初めて「スキャン書籍を最後まで読める」状態になった。その通読検証と、`data/input/Booksample/` の4冊を対象にした実測調査で、章分割そのものの不具合が3件顕在化した。いずれも `PDFSplitter` にあり、Spec B とは独立した既存バグである。

- **I-22**: 章境界の物理ページ補正が誤り、隣接章の内容が数ページ単位で混入する（`corfrapdf.pdf` で確認）
- **I-24**: PDF のネイティブ outline を無検査で信頼し、ページラベル由来のゴミを章目次として採用する（`PSEpdf.pdf` で確認）
- **I-25**: TOC 抽出のサンプリング窓が先頭15ページ固定で、目次が窓外にある書籍を分割できない（`Naven.pdf` で確認）

本スペックは3件を「章分割の正確さ」という単一主題として扱う。3件は経路上で連結している。

```
Route 2 (outline)  ──[I-24: 無検査で採用]──> ゴミ章175個
      │ 妥当性検査で棄却
      ▼
Route 3 (LLM TOC)  ──[I-25: 窓が届かず空]──> 単一章フォールバック
      │ 窓を拡げて目次を取得
      ▼
_apply_content_scan ─[I-22: 誤マッチ+先勝ち]─> 章境界ズレ
```

上流を直さないと下流の修正が効く経路に到達しない。I-24 を直すと PSE が Route 3 に落ち、I-25 を直すと Naven が `_apply_content_scan` に到達する。3件は噛み合う。

## 2. 実測で確定した事実

`data/input/Booksample/` の4冊を実測した。構造がそれぞれ異なり、そのまま設計の制約になった。

| 書籍 | 頁 | outline | 経路 | 性質 | 状態 |
|---|---|---|---|---|---|
| corfra（見開きスキャン） | 212 | 0 | Route 3 | オフセット +8 で全巻一定 | **I-22 発症** |
| relations（デジタル） | 282 | 0 | Route 3 | オフセットが部扉ごとに +7→+9→+11→+13 と階段状 | 全12章正常 |
| Naven（粗OCRスキャン） | 380 | 0 | Route 3 | ヘッダーのタイトルと頁番号が別行。目次が idx 16〜24 | **I-25 発症**（分割に到達せず）。修正後は判定順序が逆転する難所 |
| PSE | 175 | **175** | **Route 2** | outline が `f1…f175` のページラベル | **I-24 発症** |

### 2.1 I-22 の根本原因

`_matches_heading()` が章タイトルページではなく**ランニングヘッダーと本文行に誤マッチ**し、`_apply_content_scan()` が**最初のヒットで `break`** する（first-match-wins）ため、誤った候補が採用される。

決定的なのは `pdf_splitter.py` の `line_norm.startswith(norm_title + " ")`。corfra の奇数頁ヘッダー `Knowing | 147` は正規化すると `"knowing 147"` になり、`"knowing 147".startswith("knowing ")` が真になる。**章内の全奇数頁がマッチする。**

corfra の正解データと現行挙動:

| 章 | TOC論理頁 | 真の扉頁 | 現行の着地 | 一致の種類 |
|---|---|---|---|---|
| 3 Place | 69 | idx 77 | idx 77 ✓ | exact |
| 4 Things | 85 | idx 93 | idx 89 ✗ | prefix（本文 `things, and it is against them…`） |
| 7 Knowing | 145 | idx 153 | idx 155 ✗ | header（`Knowing \| 147`） |
| 8 Anonymous Introduction | 163 | idx 171 | idx 173 ✗ | header |

報告済みの2症状はこれで完全に説明される。`06_4_Things.pdf` 冒頭の第3章内容混入は開始が4頁手前にズレたため。`09_Knowing.pdf` 末尾の第8章タイトル混入は、次章の開始が2頁遅れ `end_page = 173-1 = 172` が第8章の扉頁(171)を飲み込んだため。

なお当初報告にあった「ページ順そのものが前後している」は誤読だった。偶数頁のヘッダーは章名を含まない汎用形式（`164 | Corsican Fragments`）のため、第8章の164頁が第7章の続きに見えただけである。`insert_pdf(from_page, to_page)` は連続範囲であり、ページ順は正常。

### 2.2 Knowing は原理的にテキスト照合できない

真の扉頁 idx 153 の内容はエピグラフのみで、**`7` も `Knowing` もテキスト層に存在しない**（大見出しの文字が抽出されていない）。照合すべき文字列が無いため、どんなテキストマッチでもこの頁には到達できない。

救済策は、当たったヘッダー頁から**局所オフセット**を読むこと。idx 155 のヘッダー `Knowing | 147` から `155 − 147 = +8` を得て、TOC の論理頁 145 に加えると **153** が得られる。書籍全体のページ番号マップは不要で、既に当たった1頁だけを見る。

検算（corfra、全章一致）:

| 章 | TOC論理 | 真の扉頁 | 論理 + 局所オフセット |
|---|---|---|---|
| 3 Place | 69 | 77 | 69+8 = 77 ✓ |
| 4 Things | 85 | 93 | 85+8 = 93 ✓ |
| 7 Knowing | 145 | 153 | 145+8 = 153 ✓ |
| 8 Anonymous Introduction | 163 | 171 | 163+8 = 171 ✓ |

### 2.3 Naven が否定した設計案（重要）

> **前提**: Naven は 2.6（I-25）の修正によって初めて `_apply_content_scan` に到達する。以下の危険は I-25 修正後に現実化するものであり、修正を本スペックに含めるため実データで検証可能になる。



当初は「`exact`（単独行完全一致）を `joined`（冒頭行の結合一致）より優先する」というスコアリングを想定した。**Naven はこれを反転させる。**

```
idx 58（本文頁＝誤答）              idx 200（真の章扉＝正解）
  'The Concepts of Structure...'      'CHAPTER'
  '29'                                'XIII'
  'not more so than is...'            'Ethological Contrast, Competition'
                                      'and Schismogenesis'
```

Naven はヘッダーのタイトルと頁番号が別行にある。そのため**本文頁のヘッダー行が `exact` になり、真の章扉はタイトルが2行に割れて `joined` にしかならない**。`exact > joined` を採用すると Naven では全章がランニングヘッダーに着地する。

したがって**一致の種類を順位付けに使ってはならない**。3冊すべてを貫く判別軸は次のものである。

> 一致したタイトル行の**隣接行が「裸のページ番号」か、それとも「章マーカー（`CHAPTER`・数字・ローマ数字）ないし無し」か**

| 事例 | 隣接 | 判定 |
|---|---|---|
| corfra 本文 `Knowing \| 147` | 同一行に番号 | ヘッダー |
| corfra 扉 `4` / `Things` | 章番号 | 扉 |
| Naven 本文 `The Concepts…` / `29` | 裸の番号 | ヘッダー |
| Naven 扉 `CHAPTER` / `XIII` / `Ethological…` | 章マーカー | 扉 |
| relations 扉 `1. Experimentations…` | 裸の番号なし | 扉 |

### 2.4 採用しなかった案：大域的オフセット表

「全頁の余白から印刷頁番号を抽出しオフセット表を作る」案は**破棄した**。理由は実測に基づく。

- 既存の探索窓 `logical−5 … logical+49` は corfra（+8）と relations（+7〜+13）の両方で真の扉頁を既に含む。オフセットは**位置決めには寄与せず、順位付けにしか使えない**。順位付けはスコアリングで足りる
- 抽出が書式依存で脆い。余白帯の閾値、Index の参照番号、章番号などが混入し、5回の試行すべてで別の破綻を起こした
- 章の単調性（既に `last_found_phys` で半分実装済み）が、オフセットが与える情報の代替として頑健

局所オフセット（2.2）は「既に当たった1頁のヘッダーだけを読む」ものであり、この破棄した案とは別物である。

### 2.5 I-24 の根本原因

`_get_chapters_from_outline()` は `doc.get_toc()` の結果を**妥当性検査なしで**章リストとして返す。PSE の outline は 175頁の PDF に対し `f1, f2, f3 … f175` の175件（全て level 1）で、スキャンソフトが付けたページラベルである。

`_classify_role("f1")` は既定の `"chapter"` を返し、`target_roles` を全件通過する。結果、**1頁＝1章の章PDF が175個生成され、その各々が `BookManager` で5フェーズのパイプラインを完走する**。本来は Chapter 1〜10 程度の本であり、約17倍のユニット数と全フェーズ分の LLM 呼び出しが発生する。

Route 2 は Route 3 より優先されるため、**I-22 を修正しても PSE はこの経路に到達しない**。

### 2.6 I-25: TOC 抽出のサンプリング窓が固定で、目次が窓外の書籍を分割できない

`_extract_toc()` はテキスト抽出を先頭15ページ（`range(min(15, len(doc)))`）、VLM フォールバックを先頭10ページに固定している。Naven の目次は **idx 16〜24** にあり、**両方の窓の外**である。

実測: Naven のサンプルテキストは 4,199字のみで `Contents` / `CONTENTS` を含まない。他3冊は目次が idx 2〜6 にあり窓内。

結果、Naven は `toc_data` が None のまま `split()` の「全編を単独章として扱います」分岐に落ち、**380ページの書籍が単一ユニットとして処理される**。章分割そのものが行われないため、I-22 の修正対象である `_apply_content_scan` にも到達しない。

これは I-22 / I-24 とは独立した3つ目の不具合であり、Naven にとっては最も影響が大きい。

## 3. 設計

`_apply_content_scan()` の探索窓と骨格は保ち、判定部を差し替える。Route 2 には妥当性検査を追加する。

### 3.1 ランニングヘッダーの分類（`_classify_match`）

一致したタイトル行について、次を判定して種別を返す。

- **header**: 同一行の残余が数字のみ（`Knowing | 147`）、または隣接する非空行が裸の頁番号のみ（Naven の `The Concepts…` / `29`）
- **title**: 隣接する非空行が章マーカー（`CHAPTER`、アラビア数字、ローマ数字）、または隣接に裸の頁番号が無い
- 頁番号の認識は OCR 崩れに耐えること（`3 I` → 31、`r 72` → 172 の実例がある）。数字と誤認されやすい文字の正規化を行い、確信が持てない場合は header と判定しない

### 3.2 候補スコアリング（first-match-wins の廃止）

窓内の全候補を集めて採点し、最良を選ぶ。

- 加点: `title` 分類 / 隣接行が章マーカー / ページ総文字数が少ない
- 減点: `header` 分類（強い減点）
- **`exact` と `joined` は順位付けに使わない**（2.3 の理由）
- 必須条件: 前章の開始位置より後（`last_found_phys` による単調性）

### 3.3 複数行タイトルの結合照合

Pass 2 の「4語以上」ゲートを撤廃し、短いタイトルにも結合照合を適用する。`8` / `Anonymous` / `Introduction` を拾うために必要。

> **依存関係（必須）**: この変更は 3.2 のスコアリングなしに単独で出荷してはならない。実測で、ゲート撤廃のみを適用すると corfra の `3 Place` が正解の idx 77 から idx 73（本文 `Mystery | 65 slowly snakes up…` への結合誤マッチ）へ**退行する**ことを確認している。

### 3.4 局所オフセットによる救済

最良候補が `header` 分類だった場合のみ発火する。

1. その頁のヘッダーから印刷頁番号 P を読む（同一行・隣接行の双方を見る）
2. 局所オフセット = `phys_idx − P`
3. 予測開始位置 = `TOC論理頁 + 局所オフセット`
4. 単調性を破らない場合のみ採用する

relations では全12章が `title` 分類で当たるため**この処理は一度も発火しない**（実測確認済み）。回帰リスクは無い。

### 3.5 Route 2 の妥当性検査

`_get_chapters_from_outline()` が返す前に、章目次として妥当かを検査する。妥当でなければ `None` を返し Route 3 へ落とす。

棄却条件（いずれか該当で棄却）:

- エントリ数 ÷ 総頁数 の比が高すぎる（PSE は 175/175 = 1.00。章目次なら通常 0.1 未満）
- タイトルが連番のページラベル形式（`f1, f2, f3 …` のように共通接頭辞＋連番が大半を占める）
- 1章あたりの平均頁数が小さすぎる（閾値は定数として先頭に定義する）

棄却時はその理由を `print_log` に出す。

### 3.6 TOC 抽出のサンプリング窓（I-25）

`_extract_toc()` の固定窓（テキスト15ページ / VLM 10ページ）をやめ、目次ページを探索する方式に改める。

- 先頭から一定範囲（定数としてファイル先頭に定義。Naven の idx 24 を確実に含む値とする）を走査し、`Contents` / `TABLE OF CONTENTS` 等の見出しを持つページを検出する
- 検出できた場合はその周辺ページを LLM に渡す。検出できない場合は従来どおり先頭から既定ページ数を渡す
- 走査範囲・既定ページ数はハードコードせず定数化する（プロジェクト方針）
- VLM フォールバック側の窓も同じ探索結果を使う

窓を単純に拡げるだけでも Naven は救われるが、LLM に渡す入力が全書籍で増えコストが上がる。目次ページを特定して周辺だけを渡す方が、入力量を抑えつつ窓外の目次に届く。

### 3.7 ドキュメントの訂正

`_apply_content_scan()` の docstring は「オフセットは章ごとに変動するためページ番号への依存を断つ」と述べるが、実測ではこれが正しい本（relations）と誤りの本（corfra は全巻一定）がある。オフセットの挙動は PDF の作られ方に依存し予測できない、という事実に合わせて記述を改める。

## 4. 検証

### 4.1 単体テスト（`tests/unit/test_pdf_splitter.py` に追加）

実測値をそのまま期待値にする。

- ランニングヘッダー誤マッチの回帰テスト: `Knowing | 147` 形式（同一行）と `The Concepts…` / `29` 形式（別行）の双方が `header` に分類されること
- 本文誤マッチの回帰テスト: `things, and it is against them that…` が扉頁より上位に来ないこと
- 複数行タイトル: `8` / `Anonymous` / `Introduction` が2語タイトルでも一致すること
- `3 Place` 退行防止: 結合照合を有効にしても idx 77 が idx 73 より上位になること
- 局所オフセット: ヘッダー `Knowing | 147` を idx 155 に置いたとき、論理145 から 153 が導かれること
- Route 2 妥当性検査: `f1…f175`（175頁）の outline が棄却され `None` が返ること。正常な outline は通過すること
- TOC ページ探索: 目次が先頭15ページより後（Naven 相当の idx 16〜24）にある文書で、目次ページが検出されること

### 4.2 実 PDF による全章確認

4冊すべてで `PDFSplitter.split()` を実行し、生成された章 PDF の先頭・末尾頁を実測して境界を確認する。**VLM フルランは不要**（Route 3 の LLM TOC 抽出1回のみ、キャッシュ有効）。

- **corfra**: 4章の着地が 77 / 93 / 153 / 171 になること。`06_4_Things.pdf` 冒頭に第3章のヘッダーが無いこと、`09_Knowing.pdf` 末尾に第8章タイトル頁が無いこと
- **relations**: 12章の着地が 8, 14, 36, 56, 80, 82, 106, 126, 128, 150, 172, 174 のまま**変化しない**こと（回帰の見張り番）
- **Naven**: 目次（idx 16〜24）が抽出され、章分割が行われること。各章が章扉に着地し、ランニングヘッダー頁に着地しないこと（3.1 の隣接判定を実データで検証する唯一の書籍）
- **PSE**: Route 2 が棄却され Route 3 に落ちること。落ちた先で章数が目次相当になるかは**実装時に確認する事項**であり、本スペックでは前提としない（Route 3 が PSE の目次を正しく扱えるかは未検証）
