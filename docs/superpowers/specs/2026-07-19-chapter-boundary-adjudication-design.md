# 章境界の逸脱検出と LLM 裁定（I-26 / I-27）設計

- 日付: 2026-07-19
- 対象: `core/engine/p1_ingest/pdf_splitter.py`、`scripts/verify_chapter_boundaries.py`
- 関連課題: I-26（Naven のリガチャ崩れによる誤着地）、I-27（PSE のランニングヘッダーが書名）
- 前提スペック: `2026-07-19-chapter-splitting-accuracy-design.md`（I-22 / I-24 / I-25、マージ済み）
- 本スペックの範囲外: I-21（VLM スライディング OCR の頁重複）は別スペックとして同一ブランチで後続

## 0. 着手時に判明した前提の誤り（最重要）

`scripts/verify_chapter_boundaries.py:246` は元PDFを直接 `PDFSplitter.split()` に渡している。
しかし実パイプラインは `core/book_manager.py:182-185` で、見開きスキャンPDFを
`is_spread_pdf()` で検出し `split_spread_pdf()` で単ページに分割してから
`PDFSplitter.split()` に渡す。

`is_spread_pdf()` の実測値は corfra=True、PSE=True、Naven=False、relations=False。
したがって **PSE と corfra について、検証スクリプトは実パイプラインが一度も見ることのない
文書を検証していた**。

この誤りが I-27 の診断を歪めていた。

| 項目 | 旧診断（元PDF・175頁） | 実測（分割済み・350頁） |
|---|---|---|
| 章数 | 13→10（3章スキップ） | 13章すべて配置 |
| 照合失敗 | 13章中12章 | 13章中3章 |
| 範囲外→索引頁複製 | 発生 | 発生せず |

I-27 の主症状として記録されていた「範囲外フォールバックによる索引頁複製」は
**本番では発生し得ない**。実像は「3章がフォールバックに落ち、境界が数頁ずれる」である。

I-26（Naven）は `is_spread=False` のためハーネスと本番が一致しており、診断は有効。

副次的に、マージ済みの I-22/I-24/I-25 が主張する「実PDF 4冊で退行0件」も、
4冊中2冊について誤った文書に対する検証だったことになる。本スペックの再ベースラインが
その回帰チェックを兼ねる（2026-07-19 実測では corfra・PSE とも正しい文書上で健全に動作しており、
退行は確認されていない）。

## 2. 設計

### 2.1 全体構造

既存の照合ループ（`_classify_match` / `_score_candidate` / `_rescue_by_local_offset`）は
**一切変更しない**。I-22 で4冊の実測に裏付けられた挙動であり、手を入れる合理性がない。
追加するのは、ループが出した結果を後段で見直す2つの層である。

```
既存: 章ごとに窓を走査 → 最良候補 or フォールバック → 結果
                                    ↓
      [層2] 前後の確定章とのオフセット整合性を検査し「要審査」を印付け
                                    ↓
      [層3] 要審査の章だけ LLM に扉頁を裁定させる（返り値は機械検証）
                                    ↓
                                  結果
```

この形を選ぶ理由:

1. 層2・層3は「要審査」の章にしか触れないため、現在正しい境界は定義上そのまま通過する
2. I-26（誤着地）と I-27（フォールバック）が「局所オフセットからの逸脱」という
   同一のシグナルで捕まり、1機構でカバーできる
3. ヒューリスティックの増殖が止まる。`pdf_splitter.py` は書籍が1冊増えるごとに
   ルールが1つ増える構造になっていた（`_OCR_DIGIT_MAP`、`_rescue_by_local_offset` 等）。
   新しい崩れ方が出ても層3が吸収する

### 2.2 層2: 逸脱の検出

**判定規則**:

> 前の確定章と次の確定章の双方とオフセットが食い違う章のみを「要審査」とする。
> フォールバックに落ちた章は無条件に「要審査」とする。

「確定章」は本文照合で位置が決まった章に限る（フォールバック章は参照に使わない）。

全4冊での検証:

| 事例 | 前 / 後 | 実測 | 判定 | 正誤 |
|---|---|---|---|---|
| Naven VII | +30 / +30 | +31 | 要審査 | 正（I-26） |
| Naven XII | +30 / +30 | +37 | 要審査 | 正（I-26） |
| relations「3. Expansion」 | +12 / +10 | +10 | 通過 | 正（後と一致＝正当な段差） |
| relations「Coda to Part I」 | +12 / +10 | +12 | 通過 | 正（前と一致） |
| relations Notes | +8 / +8 | +45 | 要審査 | 正 |
| relations「Introductions」 | +0 / +12 | +14 | 要審査 | **誤検知の見込み**（§4 で確認） |
| PSE Ch5 | −3 / −4 | +7 | 要審査 | 正（新規発見） |
| PSE Ch1-II | −3 / −3 | +9 | 要審査 | 正 |
| PSE Ch7 / Ch8 / Writing societies | — | フォールバック | 要審査 | 正（I-27） |
| corfra 全章 | +9 / +9 | +9 | 通過 | 正（誤検知ゼロ） |

**前付けの誤検知が自動的に消える**のが本規則の副産物である。Acknowledgments や Preface は
前の参照章が存在せず「双方と食い違う」を評価できないため対象外になる。ローマ数字による
別の頁体系を特別扱いする必要がない。

要審査の件数は corfra 0件・Naven 2件・relations 2件・PSE 5件と有界である。

### 2.3 層3: LLM 裁定

**発火**: 要審査と印付けされた章のみ。1章につき1回の呼び出し。

**入力**: 期待位置（前後の確定章から補間したオフセット × その章の論理頁）を中心とした
**±8頁**の候補頁。各候補頁の冒頭15行（`HEADING_SCAN_LINES` と同じ）を物理頁番号付きで並べる。

窓を期待位置中心にすることが要点である。既存の照合窓（`logical-5 … logical+49`）は
オフセットを考慮しない非対称窓のため、Naven XII のような手前方向へのずれを
候補に含められない。

**出力**: `{"page": <物理頁番号 or null>, "reason": "..."}`。`null` は
「現状の機械照合の結果が妥当」を意味する。

**機械検証**（LLM の返り値を無条件に信じない）:

1. 窓内に収まっているか
2. 前章の開始頁より後、次章の開始頁より前か（単調性）
3. 不合格・`null`・API キー不在・例外 → **既存の機械照合の結果をそのまま維持**

3 により、層3は既存の結果を改善できる場合だけ改善し、それ以外は何もしない。
API キーなしで走る検証スクリプトや LLM 不調時でも、現行の挙動を下回らない。
誤検知（relations「Introductions」）のコストは LLM 呼び出し1回であって、誤った境界ではない。

**層2による自動補正は行わない**。「補間オフセットに引き戻す」処理は採用しない。
ずれの原因が照合側にあるとは限らず、TOC 抽出が返した論理頁自体が誤っている場合に
誤りを増幅するため。扉頁を実際に見て判断する層3に委ねる。

**モデルとコスト**: `self.model`（TOC 抽出と同じ、`BookManager` から渡される）。
入力は 17頁 × 15行 ≒ 3k トークン。書籍1冊あたり最大5回程度。
結果は既存の `CACHE_PATH`（PDFハッシュ + 章タイトルをキー）にキャッシュし再実行を無料にする。

**補正の適用後**、全章の単調性を再検査する。

## 3. I-26 / I-27 との対応

| 課題 | 本設計での扱い |
|---|---|
| I-26（Naven VII / XII） | 層2が検出（+31 / +37 vs 前後 +30）→ 層3が扉頁を同定。リガチャ崩れに対する文字列正規化のルール追加は**行わない** |
| I-27（PSE） | フォールバック3章を層2が無条件に要審査とし、層3が扉頁を同定。「ランニングヘッダーが書名」という前提崩れを、章タイトル照合に依存しない経路で迂回する |
| I-27 の C2（範囲外クランプ） | **残す**。防御としては有用。ただし正当化の根拠（範囲外フォールバックの実害）はハーネスの副産物だったため、記録を訂正する |

## 4. テストと検証計画

### 4.1 検証ハーネスの修正（最優先）

`scripts/verify_chapter_boundaries.py` に `is_spread_pdf()` / `split_spread_pdf()` を入れ、
`book_manager.py:182-185` と同じ前処理を通してから `PDFSplitter.split()` を呼ぶ。

副作用として PSE と corfra の期待値定数を全面的に取り直す（文書が 175→350頁、106→212頁 に
変わるため）。§1 のベースラインを出発点とする。

これを先に行わないと、以降のすべての検証が無効になる。

### 4.2 正解データの確定（実装前）

- Naven VII → 物理116、XII → 物理190（オフセット30から導出済み。目視で確認する）
- PSE の Ch5 / Ch7 / Ch8 / Ch1-II / Writing societies は正解が未確定。
  候補頁のテキストを抽出して扉頁を目視同定する
- relations「Introductions」が誤検知（現状 +14 が正しい）であることを確認する

### 4.3 単体テスト（`tests/unit/`）

層2:
- 平坦（corfra 型）・階段（relations 型）・単発逸脱（Naven 型）・フォールバック混在（PSE 型）の
  各オフセット列を合成し、要審査の印付けが期待どおりか
- 前後いずれかが欠ける端（前付け・最終章）で誤検知しないこと

層3:
- 窓外・単調性違反・`null`・API キーなし・例外 の各ケースで**既存結果が維持される**こと
- 正常系で補正が適用され、単調性が保たれること

### 4.4 回帰検証

§1 のベースライン（章数・各章の頁範囲）をファイルに保存し、修正後の出力と差分を取る。

**corfra は要審査0件のため、層2・層3を通っても出力が変化しないことが期待値**である。
これが §2.1 の「既存の検証済み挙動を巻き込まない」という主張の実証になる。
