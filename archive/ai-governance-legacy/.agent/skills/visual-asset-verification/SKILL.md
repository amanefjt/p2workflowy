# 視覚的アセット検証 (Visual Asset Verification)

## 1. 目的
PDF の物理的なレイアウト（本文、ヘッダー、フッター、注釈）と、抽出されたテキスト（P2/P5）の整合性を、AI が視覚的に「目視確認」し、論理的な正しさを証明する。

## 2. 推奨ワークフロー

### 2.1. レイアウト診断 (診断フェーズ)
1. **ブラウザ起動**: `browser_subagent` を用い、対象の PDF ファイルを開く。
2. **検証ポイントの特定**: 
    - 1ページ目のメタデータ領域（タイトル、著者、Abstract）。
    - 偶数・奇数ページのヘッダー/フッター（ジャーナル名、ページ番号）。
    - 脚注（Footnotes）の区切り線。
3. **スクショ保存**: `docs/golden-rewrite/assets/` に検証箇所のスクリーンショットを保存し、アトミックな検証資料とする。

### 2.2. 抽出結果との比較 (検証フェーズ)
1. **成果物の確認**: 生成された `_p2.txt` または `_p5.md` を読み込む。
2. **論理マッピングの確認**:
    - **Metadata**: PDF 上の著者住所等が `[metadata]` に集約されているか。
    - **Header/Footer**: PDF 上のランニングヘッドが抽出結果から 100% 消えているか。
    - **Footnote**: PDF 上の脚注が、文中に割り込まず `[note]` ラベルで管理（または末尾集約）されているか。
3. **エビデンス報告**: 検証結果を「Before (PDF画像)」と「After (抽出結果)」の形式でユーザーに報告する。

## 3. ベストプラクティス
- **複数ページサンプリング**: 1ページ目、中央ページ、最終ページを少なくとも1枚ずつ確認すること。
- **2カラム対応の確認**: 2カラム論文の場合、文章がページを跨いで正しく結合されているかを、各カラムの端を確認することで検証する。
- **注釈の集約点**: 脚注が `[note]` として抽出されているだけでなく、最終的にドキュメント末尾に移動されているかを `view_file` で確認する。

## 4. 品質評価基準 (Success Criteria)
- ノイズ（Header/Footer）の混入率 0%。
- メタデータのマスク率 100%。
- 脚注の末尾集約の成功。
