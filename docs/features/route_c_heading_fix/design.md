# Design: Route C Heading Hierarchy Validation via TOC

## 背景と目的
Route C（Full VLM Mode）では、VLM が箇条書きやチャンク単位で Markdown (`# ` や `## `) を生成しますが、前後の文脈が不十分なため、単なるセクション（h3）や「柱（Running Header）」が章タイトル（h2）として誤認されることがありました。

以前は "Chapter" 等のプレフィックスがあるかを確認するハードコードされたヒューリスティックで降格させていましたが、これでは "Introduction" や "Conclusion" といった有効な章タイトルまで誤って降格させてしまうという副作用（False Negative）が発生していました。

**目的:** 前記の不完全なヒューリスティックを廃止し、ドキュメント全体から抽出した目次（TOC）と照合して `# ` 見出しの正当性を検証する堅牢な仕組みを導入する。

## 設計方針

### 1. 2パスによる構造化ロジック
単一のフェーズ内で見出しを処理するのではなく、二段階で処理を行います。
1. **Pass 1: TOCの動的抽出**
   - VLM が生成した全てのチャンクを走査し、`# ` で始まる見出しを全て収集する。
   - 収集したリストから、頻出するノイズ（柱等）を除外し、書籍の論理構造としての「目次セット」を作成。
2. **Pass 2: 目次ベースのバリデーション**
   - 木構造を構築する際、`# ` 見出しに遭遇したら「目次セット」と照合する。
   - 照合に成功すれば正規の `h2`（章）とし、失敗した場合は `h3`（セクション）に自動降格して直前の章の下にぶら下げる。

### 2. 正規化ロジックの改善 (`normalize_heading`)
照合の精度を高めるため、以下の改善を行いました。
- **プレフィックス削除の廃止**: 以前は "Chapter 1" 等を削っていましたが、現在は記号除去と小文字化のみを行い、元の文字列をできるだけ維持。
- **スペース保持**: 文字を密着させずスペースを維持することで、自然な単語境界での照合を可能にする。

### 3. レジュメモード（Paper Mode/Hybrid）への波及効果
改善された `normalize_heading` は、レジュメモードで「外部レジュメの見出し」と「本文の見出し」を照合する際にも使用されます。これにより、以前発生していた「見出しの紐付け失敗（Unlabeled Sectionの発生）」も抑制されます。

## 主要な変更ファイル
- `core/phase3_structure.py`:
  - `extract_toc_from_chunks`: チャンクから目次を抽出する新関数。
  - `structure_nodes_by_markdown`: 目次照合による階層自動調整ロジックを実装。
  - `normalize_heading`: 照合用の正規化処理を簡素化・堅牢化。
- `core/phase4_translate.py`: 
  - `pdf_mode == "full_vlm"` 時の挙動を整理。
