# PDF Routing & Structuring Design (v2.1)

本ドキュメントは、p2workflowy V2 における PDF 取り込みから翻訳・構造化までの分岐ロジックを詳細に定義する。

## 1. 全体フロー概要

パイプライン開始時、PDFの品質（CleanかDirtyか）を自動診断し、ドキュメント種別（BookかPaperか）に応じて最適な抽出ルートを選択する。

### ルーティング・マトリックス

| ドキュメント種別 | PDF品質 | ルーティング戦略 | 主な抽出エンジン |
| :--- | :--- | :--- | :--- |
| **Book (書籍)** | **Clean** | **Bipolar (Clean)** | PyMuPDF (高速テキスト/フォント抽出) |
| **Book (書籍)** | **Dirty** | **Bipolar (Dirty)** | Gemini VLM (Route C: Markdown OCR) |
| **Paper (論文)** | **Clean** | **Hybrid (Default)** | PyMuPDF + Gemini VLM (1P目/画像のみ) |
| **Paper (論文)** | **Dirty** | **Bipolar (Dirty)** | Gemini VLM (Route C: Markdown OCR) |

---

## 2. 抽出フェーズ (Phase 0/1)

### 品質診断 (`diagnose_pdf_quality`)
`pipeline.py` にて実行。以下の指標で "Dirty" を判定する。
- **異常記号密度 (3%以上)**: `~ | ^ \ _ < { } [ ]` 等。
- **単語断片化 (8%以上)**: 短い単語（1-2文字）の割合。※固有名詞やアクセント文字は除外。

### Bipolar Routing (書籍モード)
書籍の場合、ページ単位での VLM 切り替えはコンテキストの分断を招くため、**全ページ一括**で方針を固める。
- **Clean**: 全ページ Python。1ページ目の VLM 無条件呼び出しもバイパスし、高速化を図る。
- **Dirty**: 全ページ VLM。Route C (`pdf_mode="full_vlm"`) へ転送。

### Hybrid Routing (論文モード)
論文の場合、1ページ目のアブストラクト取得や、図表が含まれるページのみを選択的に VLM で補完する。

---

## 3. 構造化フェーズ (Phase 3 & 4)

構造化の挙動は `pdf_mode` によって決定的に変化する。

### Route A/B (Standard / Hybrid) の場合
- **Phase 3**: 
    - **書籍**: PyMuPDF でフォントサイズを解析し、「章（h2）」の境界線を見つける。
    - **論文**: レジュメ見出しと本文を照合し、「節（h3）」を切り出す。
- **Phase 4**: 
    - **書籍**: 章ごとに AI レジュメ（Section Resume）を生成。その中から抽出した見出しに基づき、章内を「節（h3）」にサブセクション化する。

### Route C (Full VLM) の場合
- **Phase 3**: 
    - VLM が出力した Markdown 記号（`#` / `##`）を正規表現でそのままパースする。
    - **メリット**: OCR が化けていても、VLM が認識した視覚的構造を 100% 保持できる。
- **Phase 4**: 
    - **重要**: AI レジュメベースの再構造化を**完全にスキップ**する。
    - **理由**: VLM がすでに完璧な構造を作っているため、再構造化を行うと逆に意訳された見出しで構造が壊れる（Unlabeled Section バグ）のを防ぐため。

---

## 4. 特殊処理

### ヘッダー/フッターの除去
Python ルートでは物理座標（10%以内）とキーワード、および繰り返し出現パターンを用いて除去を行う。

### スペル補正・ゴミ取り
VLM ルート (`full_vlm`) では Gemini が読み取り時に自然な修正（OCRゴミ取り）を自動的に実行するため、別途のノイズ除去は最小限に抑え、文脈を維持する。
