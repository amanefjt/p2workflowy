# 翻訳レビュー・比較読みチェックリスト

p2workflowy の翻訳品質改修（G1〜G5）の各 milestone で、**変更前後の翻訳を比較読みして品質変化を判定する**ためのガイド。

## このガイドの位置づけ

- 対象は **人文系学術論文の日本語翻訳**（哲学・芸術・質的人類学を中心とする）
- 自動メトリック（BLEU/COMET 等）は craft 評価には不適なので**使わない**
- 「理想出力」（`data/input/paperplain/*/...idealp2.txt`）は**一致度比較**ではなく**参照値・rubric** として使う
- 数値化を目的にしない。**症状の数と質**を捕捉する
- 1 milestone あたり 30〜60 分のサンプリング読みで十分

参考文献：
- 別宮貞徳『誤訳の構造』『特選誤訳迷訳欠陥翻訳』 — 翻訳批評の古典、音読の推奨
- 越前敏弥『文芸翻訳教室』 — 詳細な比較読み事例
- 安西徹雄『英文翻訳術』『翻訳英文法』 — 訳しおろし・後置修飾分割
- 池上嘉彦『〈する〉と〈なる〉の言語学』 — 無生物主語問題の言語的基盤
- 木下是雄『理科系の作文技術』、本多勝一『日本語の作文技術』 — 日本語の最低条件

## Part 1: 読む順序

**順序が最重要**。原文を先に見ると、訳文の不自然さが「原文の構造の影」として正当化されて見えなくなる。

### 推奨手順

1. **訳文だけを通読**（原文を見ない）
   - 詰まる箇所・読み返した箇所をマーク
   - 「何を論じてるか分かる？」を自問
2. **訳文を音読**
   - 黙読では気づかない不自然さが口に出すと露呈する
   - 詰まる箇所を追加マーク
3. **マークした箇所だけ**原文と並行参照
   - 原因が原文にあるのか訳の選択にあるのかを切り分ける
4. **専門用語の出現箇所一覧**
   - 検索で機械的に集める
   - 訳語が章をまたいで一貫しているか確認
5. **段落境界を 5〜10 箇所サンプル**
   - 前段落末→次段落頭の結束（cohesion）が機能しているか

**やってはいけないこと**：最初から原文と並行読みしない。網羅評価しない（サンプリングで十分）。

## Part 2: 注目ポイント（どこを見るか）

### A. 文をまたぐ流れ

| 項目 | 見方 |
|---|---|
| A1 段落冒頭文 | 前段落末からの連鎖が成立しているか。「この〜」「その〜」で受けるべきところで受けているか |
| A2 文末→次文冒頭 | 前文の rheme（新情報・末尾）と次文の theme（旧情報・冒頭）の linkage が機能しているか |
| A3 接続詞の頻度 | 英語接続詞をそのまま訳すと過剰になる。間引かれているか（「したがって」「すなわち」「一方」の連発） |

### B. 文内の処理

| 項目 | 見方 |
|---|---|
| B1 連体修飾の深さ | 「〜という〜である〜の」のような入れ子が 2 重以上発生していないか |
| B2 倒置の回数 | 1 文内で語順反転が 2 回以上ないか。3 重倒置は確実に読み手の脳に負荷 |
| B3 無生物主語 | 「X は Y を示す」が機械的に量産されていないか。「X からは〜が分かる」等への置き換え |
| B4 文末の単調さ | 「〜である。〜である。〜である。」の 3 連発以上 |

### C. 語の選択

| 項目 | 見方 |
|---|---|
| C1 漢語密度 | **接続組織**（動詞・接続詞・指示語）で漢語が連続していないか。専門術語が漢語なのは OK、つなぎが漢語なのが問題 |
| C2 「〜こと／もの／の」名詞化 | 濫用していないか。「X することは重要である」より「X は重要だ」 |
| C3 「〜という」の連発 | 1 段落に 3 回以上は要注意 |
| C4 動詞の選択 | 受動 vs 能動の判断が硬直していないか |

### D. 論証の保存

| 項目 | 見方 |
|---|---|
| D1 hedge の生死 | 原文 "may suggest" が「示唆する」と断定化していないか |
| D2 booster の生死 | 原文 "we show" の強さが「論じる」程度に弱まっていないか |
| D3 引用著者への評価 | 賛同なのか批判なのか中立なのか、訳から読み取れるか |
| D4 論文ローカル定義の一貫性 | 著者が独自定義した術語が章をまたいで一貫した訳語か |

### E. テクスト全体

| 項目 | 見方 |
|---|---|
| E1 各セクション冒頭の主張明瞭性 | そのセクションで何を論じるか、第 1 段落で分かるか |
| E2 段落の長さの分布 | 原文と大きく乖離していないか。長文を機械的に短く切ると論理が断裂する |
| E3 音読のリズム | 声に出して読んで詰まらないか |

## Part 3: 判定の感覚

### 信頼すべきシグナル

- **「詰まる」感覚**：詰まる回数が減ったら改善、増えたら劣化
- **「読み返さないと意味が取れない」箇所の数**：半客観的指標になる
- **「原文を見たくなる頻度」**：訳文だけで完結して読める割合が増えれば改善

### 数値化しない

- アスペクトメトリクス（hedge ratio、漢語密度等）は**算出しない**
- 代わりに**症状の数と質**を覚えておく
- milestone 間で「同じ症状が減ったか」「新症状が出たか」で判定する

## Part 4: milestone 実運用

p2workflowy の G2/G3/G4 等の各群を merge する前に：

1. ベンチマーク論文（推奨：`data/input/paperplain/NST/NSTsample.txt`）を**変更前**で実行
2. このチェックリストの Part 1〜2 に従って 30〜40 分読む
3. 詰まり箇所・症状をメモ
4. **変更後**で同じ論文を実行
5. 同じチェックリストで読む
6. 比較判定：
   - 同じ箇所が改善されたか
   - 新しい問題が発生したか
   - 全体感としてどちらが読みやすいか
7. 改悪と判定したら変更を戻す

### サンプリング戦略

網羅評価しない。以下のサンプリングで 90% の問題は見える：

- **1 セクション集中読み**（全文）
- **段落境界 5 箇所**（前段落末→次段落頭）
- **専門用語の出現箇所一覧**（grep で機械的に）
- **Introduction の冒頭 3 段落と Conclusion の末尾 3 段落**（主張提示部）

## Part 5: 補助的な機械チェック（任意）

機械的に確認できる項目は、目視を補助する単純スクリプトとして実装してもよい。
**評価の主体ではなく、見落とし防止のサポート**。

| 項目 | 実装案 |
|---|---|
| 用語整合性 | glossary 用語の grep + 訳語の集計 |
| 文末「〜である」連続検出 | 正規表現 |
| 「〜こと／もの／の」「〜という」濃度 | カウント |
| 文の長さ分布 | 句点で分割して長さヒストグラム |

気になったら作る。先回りして整備しない。
