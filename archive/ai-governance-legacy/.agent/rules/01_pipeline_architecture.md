# 01 パイプラインと階層 (01_pipeline_architecture.md)

## 1. 黄金律：非対称階層 (Asymmetric Golden Rule)

Workflowy の活用効率を最大化するため、以下の非対称的な階層構造を遵守します。

-   **English Original (ネスト)**: 各セクションの下にさらにサブセクション（H4/H5）を深く潜らせ、情報の「深掘り」を支援する。
-   **Japanese Translation (並列)**: 原文の内容を読みやすく、 Workflowy 上で並列（H3等）に展開し、読解のスピードを損なわない。

この階層の根拠は、常に **VLM の視覚的判断（VLM決定論）** に基づき、物理情報のイレギュラーに動じないこと。

## 2. 三位一体のデータモデル (Trinity Data Model)

`TreeNode` クラスは、単なるテキストの入れ物ではなく、以下の 3 要素を不可分に保持する「論理の核」です。

1.  **Resume (要約)**: そのノード（章・節）全体を貫く論理的な骨組み。
2.  **English (原文)**: `seq_index` によってソートされた、一次情報の「物理証拠」。
3.  **Japanese (翻訳)**: 上記コンテキストを反映した、 Workflowy フレンドリーな出力。

## 3. ポストJSON：統合ステートの志向

現在、各フェーズ（Phase 1-5）のファイルを個別に依存する「JSON管理」から、**`ProcessingContext` による統合的なメモリ内マージ**へと段階的に移行しています。

-   **メモリ・ファースト**: オブジェクト間の参照（Pointer/Ref）を優先し、ファイル I/O はチェックポイントとしてのみ機能させる。
-   **単一シリアライズ**: すべての状態（メタデータ、階層、翻訳進捗）が単一のソースから記述（Serialized）される状態を理想とする。

## 4. Route C (Full VLM) の論理降格 (Demotion Logic)

全ページ VLM モード（Route C）において、物理情報の欠如により VLM が「# 」を章（H1/H2）と誤認する場合があります。
-   **論理降格**: 明確なチャプター・プレフィックス（"Chapter", "Part" 等）を持たない「# 」見出しは、自動的に `h3` (節) へと降格（Demote）させ、既存の章に紐付けることで、不自然なタイトルの乱立を防ぐ。
