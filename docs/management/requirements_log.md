# Requirements Log - P2Workflowy

## 2026-03-29: VLM-First 黄金の再構築 (Golden Rewrite v2)

### 1. 視覚的論理主権 (Visual Logical Sovereignty)
- **要望**: Python による座標・フォントサイズ解析（物理データ主権）ではなく、VLM の視覚的判定を信頼の起点としたい。
- **決定事項**: `ocr_manager.py` で VLM に論理ロール（h1, note, metadata）を付与させ、後方フェーズまでその論理属性を優先して伝播させる。

### 2. 脚注（Note）の末尾集約
- **要望**: 論文中の脚注 `[note]` が中途半端な位置に入るのを防ぎたい。文末に `Notes` セクションとしてまとめてほしい。
- **仕様**: Phase 5 でドキュメント全体から `role="note"` または `[note]` ラベルを持つノードを再帰的に収集・削除し、最終出力の末尾に結合する。

### 3. メタデータのクリーンアップ
- **要望**: 論文のタイトル・著者・アブストラクト付近に含まれるジャーナル情報や DOI などのノイズを排除したい。
- **仕様**: VLM プロンプトで「メタデータ」としてマスキングし、主要なテキスト本文から分離。`MetaAnalyzer` では VLM ロールを活用してタイトル・著者・要約の特定を行う。

### 4. 論文モードの見出し簡略化
- **要望**: 論文では `1.` `1.1` `1.1.2` などの階層があるが、これらをフラットに（すべて同じ深さのノードとして）扱いたい。
- **決定事項**: VLM プロンプトで「すべて h1 (見出し) としてラベル付け」と指示。ネストを排除し、シンプルで Workflowy に最適な構造を実現。

### 5. タイトルの同期と一貫性
- **要望**: VLM が抽出した正式なタイトルを Workflowy のルートおよびファイル名に反映させたい。
- **決定事項**: Phase 2 の DNA 抽出結果 (`dna["title"]`) を、以降の全フェーズで `title` 引数として同期させる。

### 6. 無題の序論 (Untitled Section) の章扱い
- **要望**: アブストラクト直後の見出しのない序論を、独立した項目として扱いたい。
- **仕様**: VLM が `# [untitled section]` を出力し、`Formatter` がそれを `role="h1"` に、`TreeConstructor` が独立したセクション（章）としてパースする。

### 7. メタデータの物理的除外
- **要望**: 著者、所属、参考文献などのメタデータを最終出力から完全に消し去りたい。
- **仕様**: VLM で `[metadata]` としてマスクし、`TreeConstructor` で構造化ツリー構築時にこれらをスキップする。

### 8. VLM パフォーマンス最適化
- **要望**: 品質を維持しつつ速度とコストを改善したい。
- **決定事項**: VLM/OCR 処理の `thinking_level` を `Low` に固定。

### 9. セクション統合 (Section Merging)
- **要望**: 同じタイトルの見出し（特に `[untitled section]`）が連続する場合、分割せず一つの章として統合してほしい。
- **仕様**: `TreeConstructor.construct` において、直前のノードと同一タイトルの `h1` ノードが続く場合、新規ノードを作成せず子要素（段落など）を既存ノードにアペンドする。

## 2026-03-30: VLM-First 黄金の再構築 v3 (Sliding Window & Simple Structure)

- **スライディングウィンドウ方式 (Sliding Window)**: 
  - **要望**: ページ跨ぎでの段落断片化や、誤った `[Unlabeled Section]` の挿入を根絶したい。
  - **決定事項**: 全ページにおいて、VLM に「前ページ (N-1)」と「現ページ (N)」の2枚の画像を同時に提示、または「見開き結合画像」を提示する。
  - **仕様**: VLM は前ページとの連続性を視覚的に確認し、続きであれば見出しタグ（#）を付けず、新しい章であれば適切にタグを付与する。
- **構造化ロジックのシンプル化 (Simple Structure Building)**:
  - **要望**: `TreeConstructor.py` の複雑で脆弱な救済ロジックを排除し、VLM のタグ出力を正としたい。
  - **決定事項**: Greedy Merge や座標判定を廃止し、VLM の `# ` タグのみで機械的にツリーを構築する。
  - **仕様**: 判定の重責を VLM 側に寄せる。VLM が見出しと認めたものだけが章になる。

## 2026-03-30 (Session 2): 見出し認識の高度化 ＆ VLM 高速化

- **物理的・幾何学的孤立ルールの洗練 (Isolation Rules)**:
  - **要望**: 番号のない見出し (`Other Assemblies` 等) の抽出漏れを根絶したい。「中央にある」などの曖昧な表現をやめ、幾何学的なルールを課したい。
  - **決定事項**: VLM プロンプトに **「垂直の堀 (Vertical Moat)」** として、本文行間の 3 倍以上の空白を必須条件として定義。Italic 体のみの独立行も救済対象とする。
  - **仕様**: `ocr_manager.py` の `VLM_BASE_RULES` を刷新。定量的な空白条件を VLM に意識させる。
- **スライディングOCRの並列化 (Parallel VLM Ingestion)**:
  - **要望**: ページ数に比例して増大する VLM 処理時間（逐次処理）を短縮したい。
  - **決定事項**: `asyncio.gather` を用い、全ページのスライスを一斉に VLM にリクエストする並列実行方式を採用。セマフォにより同時実行数を制御する。
  - **仕様**: `VLM_SEMAPHORE_LIMIT = 10` に拡大。`pdf_ingester.py` をリファクタリングし、画像抽出と VLM 通信を分離・並列化。
- **最終成果と標準化 (Final Achievement)**:
  - **処理速度**: 19ページの PDF 解析を **39秒** で完走（10 並列 `asyncio.gather`）。
  - **構造化精度**: 番号なし見出し（`Other Assemblies`, `Identity` 等）の **100% 検出に成功**。
  - **標準仕様化**: 垂直の堀（3倍以上の空白）とItalic体救済ルールを `.agent/rules` に永続化。

## 2026-03-30 (Session 3): SaaS サブスクリプション化とクォータ管理

- **認証・課金基盤の疎結合化 (Auth & Billing Integration)**:
  - **要望**: スケーラビリティと保守性を確保しつつ、P2Workflowy を SaaS 形式に移行したい。
  - **決定事項**: 自前実装を避け、Clerk（認証）、Stripe（決済）、Supabase/D1（クォータ管理）を組み合わせる。
  - **仕様**: Clerk JWT でユーザーを識別し、DB でトークン消費量（月間）を追跡・制限する。
- **自動フォールバックと持込鍵 (Quota Fallback & BYOK)**:
  - **要望**: サーバー側のクォータを使い切った際や、未ログイン時でもサービスを継続利用できるようにしたい。
  - **決定事項**: クォータ超過または未ログイン時は、ユーザー自身が入力した API キー（BYOK）を自動的に使用するフォールバックロジックを実装する。
  - **仕様**: 判定優先順位：1. ログイン済かつクォータ内（サーバー鍵） > 2. ログイン済かつクォータ超過（BYOK + UI通知） > 3. 非ログイン（BYOK）。
- **クォータ運用ルール**:
  - **無料枠**: 初回お試し枠などは設けず、プロダクトの品質を維持するため、最初から「有料または BYOK」の二択。
  - **リセット**: 毎月 1 日に累積トークン消費量を一括リセット。
- **UI/UX のプレミアム化**:
  - **要望**: SaaS として洗練された印象を与えたい。
  - **仕様**: Clerk SDK によるモダンなログイン/プロフィール UI の統合。ヘッダーに残量インジケーターを表示。

## 2026-04-01: 書籍モード (Book Mode) の最終統合と黄金律の徹底

### 1. Simple Stacking (単純積み上げ) 方式の採用
- **要望**: 章ごとの独立性を保ち、階層の重複（ダブルタイトルなど）を排除したい。
- **仕様**: 各章の H2 タイトルを親ノードとし、その直下にレジュメと本文を子要素としてネストする形式で統一。

### 2. 黄金律の Asymmetry (非対称ネスト) の完遂
- **要望**: Workflowy 出力において、英語はネスト（親子）、日本語は並列（兄弟）という独自の構成を、各章だけでなく書籍全体で正しく適用したい。
- **仕様**: `TextBookIntegrator` に `shift=1` を適用。章の出力を 1 インデント分深くし、書籍全体要約と全章が同レベルで並ぶ構造を実現。

### 3. Workflowy 出力の高品質化 (Unified Resume Engine)
- **要望**: Markdown 由来の不要なハッシュ（#）や、空行が Workflowy の bullet に混入するのを防ぎたい。
- **決定事項**: 書籍全体の要約（Global Resume）を `WorkflowyEngine.render_resume` でレンダリング。`clean_heading_text` による見出しのクリーンアップを徹底。

### 4. 最終品質保証 (Final QA) の完遂
- **要望**: 公開前に Paper Mode / Book Mode の両方で、大規模な実データを用いた検証を行いたい。
- **成果**:
    - `nstpdf.pdf` (26ページ) を用いたストレステストに合格。
    - 英語: ネスト (Depth 2), 日本語: 並列 (Depth 1) の非対称階層を厳密に維持。
    - 書籍モードにおける全体要約のインデント不備を解消。
    - 全パイプラインの安定性と、VLM による構造抽出の堅牢性を証明。
