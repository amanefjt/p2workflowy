# APIトラブルシューティングと安定化 (skills/api_troubleshooting.md)

## TTFT (Time To First Token) ボトルネックの特定
- **事象**: 処理が極端に遅い（1分以上）場合、TTFTを計測して「入力待機」か「生成時間」かを分離する。
- **診断**:
    - TTFTが数十秒〜数百秒に及ぶ場合、APIサーバー側でキューイング（待機室送り）されている。
    - 生成開始後の TPS (Tokens Per Second) が良好であれば、JSON出力制約などは原因ではない。

## スロットリング回避の実践手順
1. **並列数の制限**: `asyncio.Semaphore(1)` に設定し、リクエストを一列に並べる。これによりサーバー側の「バースト検知」を回避できる。
2. **レートリミットの厳格化**: 定格内（例: 15 RPM）であっても、間隔を空けてリクエストを送るよう `aiolimiter` で調整する。
3. **ペイロードの軽量化**: 翻訳プロンプトから不要な「要約（Resume）」や過去のコンテキストを削り、入力文字数を抑制する。

## 再現性のためのログ
- `state/debug_prompt.txt` に最新のリクエスト内容をダンプし、プロンプトの不備や肥大化を常に監視できる状態にする。
