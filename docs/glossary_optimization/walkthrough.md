# Walkthrough: 語彙最適化の実験結果

## 1. 実験環境
- **入力データ**: `NSTsample.txt` (約6.7万文字)
- **使用モデル**: `gemini-3-flash-preview`
- **語彙数**: 113語（手動辞書 + AI抽出）

## 2. 比較データ

| 戦略 | 平均 TTFT | 最小 TTFT | プロンプト平均 |
| :--- | :--- | :--- | :--- |
| **Mode 0 (Baseline)** | **17.52s** | **10.49s** | 約 4,870 tk |
| **Mode 1 (Dynamic)** | 28.62s | 14.76s | 約 4,120 tk |
| **Mode 2 (Global)** | 24.31s | 13.25s | 約 4,340 tk |

## 3. 分析結果のサマリー
- **「プロンプトが小さい ＝ 速い」とは限らない**: チャンクごとに語彙を絞り込んでプロンプトを数百トークン節約するよりも、**「固定されたコンテキスト（語彙・要約）を繰り返し送る」** 方が Gemini の内部キャッシュが効き、初回リプライまでの時間が短縮されることがわかった。
- **要約（Summary）の重要性**: 文脈維持のために必須であり、実験中も常に含めることで品質を担保した。

## 4. 運用方法
- **メトリクスの確認**: `state/ttft_metrics.csv` をスプレッドシート等で開くことで、各バッチの処理時間を確認できる。
- **語彙の追加**: `data/glossary.csv` に追記するだけで、自動的に AI 語彙とマージされて翻訳に反映される。
