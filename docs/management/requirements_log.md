# Requirements Log

- **2026-03-15**: 
    - **Workflowyフォーマットの厳守**: 生成される `.txt` ファイルは Workflowy のインポート形式（タブ + `- `）を完全に満たしている必要がある。
    - **不自然な行分割の抑制**: アカデミックな引用（コロンや `cf.` 等）によって、1つの文が複数の箇条書きに分割されるのを防ぐ。
    - **日本語翻訳の品質向上**: 書籍モードの翻訳において、見出しの整合性を保ち、未分類セクションを最小限にする。
- **2026-03-15 (V2.9.2)**:
    - **API遅延への耐性 (Observability)**: APIが長時間（数分〜）沈黙している場合でも、ハングと区別できるようバッチごとの詳細ログを出力すること。
    - **強制タイムアウトと自動復旧**: 応答が10分（600秒）を超えた場合はエラーとして検出し、自動的にリトライを行うことで、無期限の待機を防止する。
- **2026-03-15 (V2.9.8)**:
    - **レジュメ再利用 (デバッグ高速化)**: Phase 2 の生成結果 (`phase2_meta.json`) が存在する場合、LLMへの問い合わせをスキップして即時に再利用し、開発・調整サイクルを高速化する。
    - **利便性向上 (ショートカット)**: 書籍要約モード専用 `p2wbr` 等のエイリアスを整備。対話的なパス入力、不要な引数の除去、および引用符の自動クレンジングを実現。

- **2026-03-16 (V3.2.3)**:
    - **リアルタイム・トレーサビリティ**: `/api/trace` エンドポイントと Web UI 上のターミナル風ビューアにより、バックエンドの処理状況（LLMの思考等）をリアルタイムで追跡可能に。
    - **環境透過型ビルド**: `app.js` にて `hostname` を判定し、ローカル開発環境と HuggingFace Spaces 環境で API Base URL を自動的に切り替えるロジックを実装。
    - **リポジトリの軽量化とバイナリ制限回避**: `git filter-branch` により、10MBを超える過去のサンプルPDF履歴を完全に抹消し、HuggingFace Spaces へのスムーズなデプロイを可能にした。

- **2026-03-16 (V3.2.8)**:
    - **パスコード認証の安定化**: 前バージョンでの実装ミス（未定義変数 `task_id` への参照）による 500 エラーを解消。Hugging Face の Secrets との同期も確認され、合言葉を入力することで管理者用 Gemini API キーを安全かつ確実に利用できることを実証した。
    - **物理ストレージの自律管理**: `shutil.rmtree` による物理削除を実装し、Hugging Face の限られたストレージを圧迫しない長期運用体制を整えた。

- **2026-03-16 (V3.2.9)**:
    - **UI文言の洗練（対象拡大）**: 「学術論文」から「学術論文・学術書」へ表記をアップデートし、学際的な書籍要約ツールとしての位置づけを明確化。
    - **UXの改善**: PDFアップロードに関する注釈（Note）を、実情（Betaの不安定さ強調から処理時間の説明へ）に合わせて調整し、Word経由での入力をより自然に推奨する形に書き換え。
