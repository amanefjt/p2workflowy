# AI駆動型リファクタリング手順書：黄金の再構築 (refactoring-best-practices)

## 概要
AI エージェントが大規模なコードベースをリライトする際の「デグレード防止」と「正確な移植」を担保するための技術手順。

## 1. 監査とコード抽出 (Audit & Extract)
- 既存の冗長なコードから「機能部（Regex, Threshold, Calculation）」のみを抽出し、`technical_audit_results.md` 等の事実に基いたレポートを作成する。
- 変数名やメソッド名が変わる場合、以前の挙動（I/O）を保存し、互換性を保証する。

## 2. ファイルサイズと責務の制約 (300-Line Rule)
- 1つの Python ファイル/クラスは、原則として **300 行以内** に収める。
- ファイルサイズが増大した場合、それは「責務の混在」を意味し、速やかにモジュール（例: `detector.py`, `formatter.py`）へ分割することを検討する。

## 3. インターフェース先行実装 (Interface First)
- ロジックを実装する前に、`models.py` においてデータの「型」と「プロパティ」を確定させる。
- すべてのフェーズはこの「型」のみを通じて会話し、独自の辞書キーの追加による「汚染」を防止する。

## 4. 検測第一 (Verification First)
- 関数を 1 つ実装するごとに、`verification-before-completion` スキルを実行。
- 特に正規表現を変更した際は、監査時に作成した「成功パターン」での単体テストを強制する。

## 5. ロジックのピュア化
- `if is_book:` のような分岐をコアロジックから排除し、戦略パターン（Strategy Pattern）等によるクリーンな分離を目指す。
