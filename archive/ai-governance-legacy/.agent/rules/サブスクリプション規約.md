# サブスクリプション・クォータ運用規約 (subscription_rules.md)

## 1. 原則
P2Workflowy の SaaS 運用において、サーバーコストの制御とユーザーの利便性を両立させるため、以下のクォータ管理およびフォールバックルールを厳守しなければならない。

## 2. 権限と優先順位 (Auth Priority)
API 実行時、使用する API キーおよびモデルは以下の優先順位に従って決定される。

1. **Managed Pro (有料枠)**:
   - 条件: ログイン済み かつ 当月トークン消費量がクォータ上限（例: 2M tokens）以下。
   - 挙動: サーバー側の `GEMINI_API_KEY` を使用。高品質モデル（1.5 Pro 等）を割り当てる。
2. **BYOK Fallback (持込枠)**:
   - 条件: ログイン済み かつ 当月トークン消費量がクォータ上限を超過。
   - 挙動: ユーザーがフォームに入力した API キーを使用。UI にてフォールバック状態を明示する。
3. **Anonymous BYOK (非ログイン)**:
   - 条件: 未ログイン。
   - 挙動: ユーザー提供の API キーを必須とする。サーバー鍵は一切使用しない。

## 3. クォータ計測規約 (Measurement)
- **集計単位**: 全フェーズの `usage_metadata` (prompt + candidates) の合算。
- **記録タイミング**: 各フェーズの API コール成功直後に DB (Supabase/D1) へアトミックに加算する。
- **リセット周期**: **毎月 1 日 0:00 (JST)** に全ての `tokens_used` を 0 にリセットする。

## 4. UI/UX ガードレール
- **透明性**: 有料ユーザーに対しては、常に「現在の消費パーセンテージ」を可視化すること。
- **告知**: クォータ超過による BYOK への切り替え時は、処理を中断せず、トーストまたはステータス欄でユーザーに通知すること。

## 5. 禁止事項
- **クォータの踏み倒し**: ログイン済みでありながら、個人の API キーを入力することでサーバー側のクォータ消費を回避する「意図的な使い分け」は許容する。ただし、サーバー鍵を使用する場合は必ず DB への記録を伴わなければならない。
- **過剰な試用**: 「最初のお試し無料枠」は、スパム防止のため原則として設定しない。
