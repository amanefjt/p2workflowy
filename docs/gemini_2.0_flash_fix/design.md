# Design: Gemini 2.0 Flash 構造解析の安定化

## 背景と課題
Gemini 2.0 Flash を使用した場合、モデルの特性（要約の流暢さを優先し、厳密な書式指示を軽視する傾向）により、Phase 2 で生成される要約（Resume）の構造が崩れる問題が発生した。
具体的には：
- 見出し（H2）の前に「要約を開始します」等の前置きが含まれる。
- 見出しのレベル（#の数）が H5 や H6 になり、Phase 3 の正規表現 `^#\s+\[` にマッチしない。
- これにより、すべての文章が `[Unlabeled Section]` に統合され、ドキュメントの構造が失われる。

## 設計方針
1. **専用プロンプトの導入**: `gemini-2.0-flash` の命令追従性を考慮し、書式遵守を最優先かつ命令的に指示する専用プロンプト `SUMMARY_PROMPT_ronbun` を定義する。
2. **モデル別ロジックの分岐**: システム側で現在使用しているモデルを検知し、Gemini 2.0 系の場合にのみ上記プロンプトへ自動で切り替える。
3. **書式の固定**: 前置きの厳禁と、見出しの開始文字（#）を1文字目に持ってくることを強く指示する。

## 実装詳細
- `core/coreprompts.json`: `SUMMARY_PROMPT_ronbun` を追加。
- `core/phase2_meta.py`: `generate_resume` 関数内でモデル名をチェックし、プロンプトを切り替える。
- `main.py`: CLI から `--model` を手動指定可能にし、検証を容易にする。

## 採用の根拠 (Rationale)
共通のプロンプトを複雑化して全モデルに対応させるよりも、モデルの特性に合わせた専用プロンプトを用意する方が、メンテナンス性が高く、かつ各モデルの最高性能を引き出せると判断した。
