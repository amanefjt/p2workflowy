## 0. 着手時に判明した2つの前提の誤り

本スペックは、既存の記録が2箇所で事実と異なっていたことを出発点とする。

### 0.1 検証ハーネスが実パイプラインと異なる文書を検証していた

`scripts/verify_chapter_boundaries.py:246` は元PDFを直接 `PDFSplitter.split()` に渡す。
実パイプラインは `core/book_manager.py:182-185` で `is_spread_pdf()` により見開きスキャンを
検出し、`split_spread_pdf()` で単ページに分割してから `PDFSplitter.split()` に渡す。

実測: corfra=True、PSE=True、Naven=False、relations=False。
つまり **PSE と corfra について、検証は実パイプラインが一度も見ない文書に対して行われていた**。

I-27 に記録された主症状「範囲外フォールバックによる索引頁複製」は、この誤りの産物である。

| 項目 | 旧診断（元PDF・175頁） | 実測（分割済み・350頁） |
|---|---|---|
| 章数 | 13→10（3章スキップ） | 13章すべて配置 |
| 範囲外→索引頁複製 | 発生 | 発生せず |

副次的に、マージ済み I-22/I-24/I-25 の「実PDF 4冊で退行0件」も4冊中2冊が誤った文書での
検証だったことになる。本スペックの再ベースラインがその回帰チェックを兼ねる
（2026-07-19 実測では corfra は正しい文書上でも健全であり、退行は確認されていない）。

### 0.2 I-27 の原因は「ランニングヘッダーが書名」ではなく TOC 抽出の系統的ずれ

I-27 は「PSE のランニングヘッダーが章名でなく書名のため、コンテンツスキャンが構造的に
機能しない」と記録されていた。実測はこれを否定する。

**PSE の奇数頁（recto）ランニングヘッダーは章タイトルを載せている**
（例 P150: `Divisions of Interest` / `137`）。書名が出るのは偶数頁（verso）のみで、
これは組版の標準的な交互配置にすぎない。

真の原因は上流にあった。各章の真の扉頁の印刷頁番号と、LLM が TOC から抽出した論理頁を
突き合わせると、**全章が1つずれて対応付けられている**。

| 章 | 真の印刷頁 | TOC が返した論理頁 |
|---|---|---|
| Ch1 | 1 | 29 |
| Ch2 | 29 | 45 |
| Ch3 | 45 | 64 |
| Ch4 | 64 | 89 |
| Ch5 | 89 | 117 |
| Ch6 | 117 | 138 |
| Ch8 | 161 | 179 |

各章が「次の章の頁番号」を受け取っている。原因は目次頁のテキスト層の構造で、
`get_text("text")` は P6 を「Contents / Preface / lX / Chapter 1…Chapter 10 /
（タイトル群）/（頁番号14個）」と**列単位**で吐き出す。Preface の頁番号 `ix` は
OCR で `lX` と読まれてタイトル列に紛れ込むため、数値列が15エントリに対し14個しかなく、
LLM がずらして対応付けた。

**この誤りは下流のどの精緻化でも回復できない。** 入力である論理頁が全章ずれていれば、
コンテンツスキャンも LLM 裁定も誤った近傍を探すだけである。

さらに、当初の調査で観測した「PSE のオフセットは −2〜−4 で揃っている」という所見は
**実在しなかった**。探索窓が `logical-5 … logical+49` と左に狭く右に広いため、
誤った論理頁の近傍で*正しい章のランニングヘッダー*にたまたま当たり、窓の左端付近が
採用されていただけである。揃って見えた数字はオフセットではなく窓の左端という人工物だった。

## 2. 設計

### 2.1 全体構造

既存の照合ループ（`_classify_match` / `_score_candidate` / `_rescue_by_local_offset`）は
**一切変更しない**。I-22 で4冊の実測に裏付けられた挙動であり、手を入れる合理性がない。
追加するのは、その前後に置く3つの層である。

```
[層1] TOC 検算: 印刷頁番号から写像を推定し、TOC の対応付けのずれを検出・補正
                            ↓
既存: 章ごとに窓を走査 → 最良候補 or フォールバック
                            ↓
[層2] 逸脱検出: 前後の確定章とのオフセット整合性を検査し「要審査」を印付け
                            ↓
[層3] LLM 裁定: 要審査の章だけ扉頁を裁定させる（返り値は機械検証）
```

層1が I-27 に、層2＋層3が I-26 に対応する。層2・層3は要審査の章にしか触れないため、
現在正しい境界は定義上そのまま通過する。

### 2.2 層1: TOC の検算とずれ補正

**手順**:

1. 全頁のヘッダー/フッター領域から印刷頁番号を回収する（§1.2）。
   同一頁から複数の異なる数値が読めた場合はその頁を棄却する（誤読の混入を防ぐ）
2. `物理 idx − 印刷頁` の**最頻値**を書籍の写像として採る。中央値ではなく最頻値を使うのは、
   relations のように複数の段が混在する場合に、実在する段のいずれかを選ばせるため
3. TOC の各エントリについて予測物理頁 `論理頁 + オフセット` を求め、
   その頁の冒頭12行にそのエントリのタイトルが含まれるかを検算する
4. エントリと頁番号の対応を `shift ∈ {-1, 0, +1}` だけずらした場合の一致数を比較し、
   最良の shift を採る

**実測による検証**:

| 書籍 | shift=−1 | shift=0 | shift=+1 | 採択 |
|---|---|---|---|---|
| **PSE** | **12/15** | 2/16 | 2/15 | −1（ずれを検出） |
| corfra | 0/12 | **6/13** | 0/12 | 0 |
| Naven | 0/16 | **11/17** | 1/16 | 0 |
| relations | 0/15 | **7/16** | 2/15 | 0 |

PSE のみ shift=−1 が 12対2 で勝ち、他3冊は shift=0 が勝つ。差が明瞭なため閾値調整を要しない。
**誤ってずれを検出した書籍はゼロ**である。

正しい shift でも一致率が100%にならないのは、扉頁のテキスト層にタイトルが無い章
（corfra の `Knowing`）や後付け（Notes/Index）が含まれるためで、shift の比較には影響しない。

**適用範囲の制限**: shift 補正は、最良 shift の一致数が次点の2倍以上かつ3件以上ある場合に
限って適用する。それ以外は shift=0（現状維持）とする。判断材料が乏しい書籍で
賭けに出ないための安全弁である。

**Ch1 の限界**: PSE では Preface の頁番号 `ix` が数値列から欠落しているため、
Ch1 の正しい頁番号（印刷頁1）はそもそも抽出結果に存在しない。shift 補正では回復できず、
Ch1 はコンテンツスキャンと層2・層3に委ねられる。扉頁 P12 は
`Chapter 1` / `The Ethnographic Effect I` を持つ疎な頁であり、既存の照合で到達可能である。

### 2.3 層2: 逸脱の検出

**判定規則**:

> 前の確定章と次の確定章の**双方と**オフセットが食い違う章のみを「要審査」とする。
> フォールバックに落ちた章は無条件に「要審査」とする。

「確定章」は本文照合で位置が決まった章に限る（フォールバック章は参照に使わない）。

全4冊での検証:

| 事例 | 前 / 後 | 実測 | 判定 | 正誤 |
|---|---|---|---|---|
| Naven VII | +30 / +30 | +31 | 要審査 | 正（I-26） |
| Naven XII | +30 / +30 | +37 | 要審査 | 正（I-26） |
| relations「3. Expansion」 | +12 / +10 | +10 | 通過 | 正（後と一致＝正当な段差） |
| relations「Coda to Part I」 | +12 / +10 | +12 | 通過 | 正（前と一致） |
| relations Notes | +8 / +8 | +45 | 要審査 | 正 |
| relations「Introductions」 | +0 / +12 | +14 | 要審査 | 誤検知の見込み（§4.2 で確認） |
| corfra 全章 | +9 / +9 | +9 | 通過 | 正（誤検知ゼロ） |

閾値を持たない規則である点が重要で、これにより relations の段差2と Naven の誤り1を
取り違えない。

**前付けの誤検知が自動的に消える**のが副産物である。Acknowledgments や Preface は
前の参照章が存在せず「双方と食い違う」を評価できないため対象外になる。
ローマ数字による別の頁体系を特別扱いする必要がない。

### 2.4 層3: LLM 裁定

**発火**: 要審査と印付けされた章のみ。1章につき1回の呼び出し。

**入力**: その章の**前後の確定章に挟まれた物理頁の区間**（上限32頁でクリップ）にある各頁の
冒頭15行を、物理頁番号付きで並べる。真の扉頁は定義上この区間内にあるため、
「論理頁 ± α」のような論理頁の正しさに依存する窓を使わない。
これは、論理頁が誤っているために要審査になった章（PSE 型）でも窓が正しく張れることを意味する。

**出力**: `{"page": <物理頁番号 or null>, "reason": "..."}`。
`null` は「現状の結果が妥当」を意味する。

**機械検証**（LLM の返り値を無条件に信じない）:

1. 区間内に収まっているか
2. 前章の開始頁より後、次章の開始頁より前か（単調性）
3. 不合格・`null`・API キー不在・例外 → §2.5 の基準値へ

**モデルとコスト**: `self.model`（TOC 抽出と同じ、`BookManager` から渡される）。
入力は最大32頁 × 15行 ≒ 6k トークン。書籍1冊あたり数回。
結果は既存の `CACHE_PATH`（PDFハッシュ + 章タイトルをキー）にキャッシュする。

補正の適用後、全章の単調性を再検査する。

### 2.5 LLM が使えない/答えられない場合の基準値

層3が結論を出せない場合の扱いは、その章がどう要審査になったかで分ける。

- **照合が成立した章**（Naven 型の誤着地）→ **既存の機械照合の結果を維持する**。
  照合が当たった頁は実在の一致であり、当て推量より安全である
- **フォールバックに落ちた章**（PSE 型）→ **`論理頁 + 前後の確定章から補間したオフセット`**
  を採る（文書範囲へクランプし、単調性を満たす範囲に収める）

後者を分けるのが重要である。フォールバックの現行値は「オフセット0」であり、
それ自体が I-27 の症状だからである。ここで機械照合の結果を維持すると、
層3が失敗した瞬間に不具合へ戻ってしまう。補間オフセットの採用は現状より悪化し得ない
（どちらも論理頁を起点とし、前者は隣接章から得た実測オフセットを足すだけである）。

なお、この基準値は層2の自動補正ではない。**照合が成立した章に対して補間オフセットへ
引き戻すことは行わない** — ずれの原因が照合側にあるとは限らず、TOC の論理頁自体が
誤っている場合に誤りを増幅するためである。

### 2.6 受容するリスク（対処せず記録する）

- **隣接する等量の二重誤り**: 隣り合う2章が同じオフセットで揃って誤っている場合、
  互いに整合するため層2は検出できない。4冊の実測には存在せず、層3にも見えないため受容する
- **最初と最後の実章**: 前または次の確定章が存在しないため「双方と食い違う」を
  評価できず、層2の検出対象外になる。後付け（Notes 等）が最終章の後に続くことが多く、
  実害は限定的と見る
- **層1の shift 補正が扱えない欠落**: PSE の Ch1 のように、正しい頁番号が
  抽出結果自体から欠落している場合は shift では回復できない（§2.2）

### 4.3 単体テスト（`tests/unit/`）

層1:
- 印刷頁番号の回収（同一頁から複数値が読めた場合の棄却を含む）
- 最頻オフセットの算出（単一の段・複数の段が混在する場合）
- shift 検出（PSE 型のずれ・ずれなし・判断材料が乏しく shift=0 に留まる場合）

層2:
- 平坦（corfra 型）・階段（relations 型）・単発逸脱（Naven 型）・
  フォールバック混在（PSE 型）の各オフセット列を合成し、要審査の印付けが期待どおりか
- 前後いずれかが欠ける端（前付け・最終章）で誤検知しないこと

層3:
- 区間外・単調性違反・`null`・API キーなし・例外の各ケースで §2.5 の基準値に落ちること
- 照合成立章は機械照合の結果、フォールバック章は補間オフセットと、
  基準値が経路によって正しく分かれること
- 正常系で補正が適用され、単調性が保たれること

### 4.4 回帰検証

§1 のベースライン（章数・各章の頁範囲）をファイルに保存し、修正後の出力と差分を取る。

**corfra は層1で shift=0、層2で要審査0件のため、出力が変化しないことが期待値**である。
これが §2.1 の「現在正しい境界は定義上そのまま通過する」という主張の実証になる。

PSE は §4.2 の正解データに対する一致章数で評価する。
